- **Decision: proceed with a capability bridge and candidate pipeline, not a bulk importer.** External engines should rank repeated capability work, suggest MTGCLI primitive decompositions, and supply scenario intent. Oracle text and the Comprehensive Rules remain the specification; a model promotes only through registered pools, exact clause accounting, native behavior tests, and the existing landing gate.
  - Phase 1 is authoritative name/registration manifests and pinned revision drift.
  - Phase 2 is a calibrated external-fingerprint-to-MTGCLI bridge labeled `exact`, `test-hint`, or `unknown`, with non-executable draft/scaffold output and no partial-IR fallback.
  - Phase 3 works exact static/keyword lanes first, then treats kicker, madness, mutate, replacement chains, linked abilities, copy/layers, hidden information, and zone identity as dedicated engine units.
  - Phase 4 translates interaction intent into original MTGCLI tests and resolves cross-engine disagreements against the rules rather than majority vote.
